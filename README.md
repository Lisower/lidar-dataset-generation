# lidar-dataset-generator

Процедурная генерация сцен и облаков точек для задач LiDAR: рельеф и вода,
здания, растения, целые территории и симуляция сканирования. Каждый генератор
показывает результат в окне и умеет работать без окна — как библиотека.

Вся генерация **детерминирована от seed**: одинаковые пресет и seed всегда дают
одинаковый результат, вплоть до облака точек.

## Быстрый старт

Всё делается из **корня репозитория**. Переходить в каталоги крейтов не нужно:
пути к пресетам и шрифтам приложение вычисляет от каталога своего крейта, а не
от текущего каталога терминала.

### 1. Поставить Rust

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs -o /tmp/rustup-init.sh
sh /tmp/rustup-init.sh -y
source "$HOME/.cargo/env"
cargo --version      # нужно 1.97.1 или новее
```

Если `cargo` уже стоит, проверьте версию. Системный `cargo` из репозитория
Ubuntu слишком старый, нужен именно `rustup`.

### 2. Поставить системные библиотеки (один раз)

Ubuntu / Debian:

```sh
sudo apt update
sudo apt install build-essential pkg-config curl libx11-dev libasound2-dev \
  libudev-dev libxkbcommon-x11-0 libwayland-dev libxkbcommon-dev
```

Для Intel/AMD без Vulkan-драйвера: `sudo apt install mesa-vulkan-drivers`.
Для NVIDIA нужен подходящий драйвер NVIDIA. Подробности в разделе «Установка».

### 3. Запустить приложение

```sh
cargo run -p landscapes-generator
```

**Первый запуск собирает Bevy и идёт десятки минут**, `target/` вырастает до
десятков гигабайт. Это нормально и происходит один раз, дальше окно открывается
за секунды. Первые секунды после открытия окна тоже уходят на компиляцию
шейдеров.

Что должно появиться: окно с рельефом и надписью о сгенерированном ландшафте в
терминале:

```
landscapes_generator::plugin: Ландшафт сгенерирован: равнина, seed = 12648430
```

Если окно не появилось, смотрите «Если не запускается».

Окно закрывается крестиком или `Alt+F4`; если запуск в терминале подвис —
`Ctrl+C` в нём.

### 4. Остальные приложения

Тот же принцип: одна команда из корня репозитория, своё окно на каждое.

| Приложение | Что увидите |
| --- | --- |
| ландшафты | рельеф, грунт и вода |
| здания | одно здание; пресет задаётся флагом |
| растения | дерево, куст или трава; `M` меняет вид |
| территории | участок 100×100 м с застройкой и растительностью |
| симулятор | здание и его скан с LiDAR-сканера |
| раннер датасетов | выбор пресетов и запуск генерации датасета |

Их команды:

```sh
cargo run -p buildings-generator
cargo run -p plants-generator
cargo run -p terrains-generator
cargo run -p lidar-simulator
cargo run -p lidar-dataset-runner
```

Здания: от частных домов (прямоугольные, Г-образные, с пристройкой) до
многоквартирных домов и небоскрёбов — 7 типов крыш, балконы, парапеты, козырьки,
слуховые окна, дымоходы. Г-образные дома и дома с пристройкой поддерживают все
типы крыш, включая обе полувальмовые; крыло размещается в одном из четырёх
углов относительно входа. У многоэтажек окна и балконы повторяются по этажам,
а пресет `multi-entrance` даёт дом с 2–4 подъездами. Балконы бывают открытыми
и остеклёнными, доля закрытых задаётся `enclosed_balcony_probability`
(по умолчанию 0.35). Хозпостройки — ангары (`hangar`), гаражи (`garage`) и
амбары (`barn`).

Дополнительные аргументы:

```sh
# пресет здания: rectangular, l-shaped, annex, apartment, multi-entrance,
# skyscraper, hangar, garage, barn
cargo run -p buildings-generator -- --preset apartment

cargo run -p terrains-generator -- --list        # названия территорий
cargo run -p terrains-generator -- village 42    # территория и seed
cargo run -p lidar-simulator -- --help           # все флаги симулятора
```

`terrains-generator` принимает аргументы позиционно (`[пресет] [seed]`), у
остальных генераторов пресеты выбираются в окне `Ctrl+S`.

Что строит каждый генератор:

- `plants-generator` — деревья (ель, высокая ель, сосна, лиственное дерево,
  ива, пальма, пальма с кокосами), кусты и траву (низкую и высокую); режимы
  одиночного растения и группы переключаются клавишей `M`;
- `terrains-generator` — композицию целой территории 100×100 м: ландшафт,
  деревья, кусты, траву и здания, расставленные с учётом рельефа и правил
  пересечений. Территории поддерживают несколько пресетов объектов, вложенные
  группы и веса, размещение у воды и застройку вдоль коридоров улиц; трава
  переиспользует ограниченный набор моделей и может расти под кронами.
  Запуск, управление и создание своего RON-пресета —
  [руководство terrains-generator](crates/terrains-generator/README.md);
- `lidar-simulator` — сканирование процедурного здания: поле зрения 90°×70°,
  дальность 0.1–150 м, перекрытия стен, крыши и деталей через AABB-дерево
  двусторонних треугольников, один видимый отсчёт на ячейку шага (по умолчанию
  0.25 м) и измерительный шум. Есть накопление кадров, орбитальные траектории
  и экспорт в PLY;
- `lidar-dataset-runner` — пакетная генерация датасетов, см. шаг 6.

### 5. Скан без окна

Симулятор умеет сохранять облако точек в файл, графическая сессия не нужна:

```sh
cargo run -p lidar-simulator -- --headless --frames 72 --seed 12648430 \
  --output assets/export/building-scan.ply
```

В консоли появятся число кадров и количество точек, а по указанному пути
окажется PLY с классами точек:

```
Кадров: 4, исходных точек: 134777, увидено: 18117, итог с Low Noise: 18547.
```

Для `terrains-generator` путь ассетов разрешается явно, поэтому его можно
запускать из корня workspace. При переносе собранной программы положите
`assets/` и полный каталог `presets/` рядом с exe. Подробнее — в
[руководстве по территориям](wiki/Генерация%20территорий.md#каталоги-данных).

Каталог `assets/export/` создаётся сам, в Git он не попадает.

### 6. Раннер датасетов

У раннера есть веб-интерфейс, его нужно собрать отдельно, иначе окно покажет
заглушку «ui не собран». Нужен **Node.js 20**:

```sh
cd crates/lidar-dataset-runner/ui && npm install && npm run build && cd -
cargo run -p lidar-dataset-runner
```

Готовый `.deb` и `.AppImage` ставятся без Node и без Rust, см. «Установка
раннера датасетов». Для правки интерфейса: `npm run dev` в
`crates/lidar-dataset-runner/ui` и параллельно `cargo run -p
lidar-dataset-runner`.

Окно разделено на две части: слева просмотр сцены, справа панель управления.

Слева облако точек: кнопка «Показать сцену» собирает сцену из текущего рецепта
и рисует её без записи файлов, перетаскивание мышью вращает камеру, колесо
меняет масштаб, «Камера» возвращает исходный ракурс. Кнопка «Показать сцену»
работает и во время запуска: предпросмотр не занимает генерирующую задачу.
После завершения запуска первая записанная сцена показывается сама, а клик по
строке в таблице результатов открывает выбранную сцену. В превью попадает не
больше 60 000 точек из облака, поэтому крупная сцена рисуется быстро и
одинаково при каждом открытии.

Справа сверху вниз идут рецепт, прогресс и таблица результатов, а внизу
закреплена панель действий, поэтому кнопка «Сгенерировать датасет» видна без
прокрутки. В рецепте задаются число сцен, сид, допустимый уклон, рельеф и
объекты с количествами; под каждым полем есть подсказка, у выбранного пресета
показывается его описание. Ошибки формы собираются в сводку, клик по строке
сводки ставит курсор в нужное поле. Значения по умолчанию дают небольшую
датасет-сцену, которую можно собрать сразу после установки; настройки и папка
вывода запоминаются между запусками, кнопка «Сбросить настройки» возвращает
исходные.

Во время запуска видно, сколько сцен уже записано, сколько точек вышло, сколько
осталось примерно ждать и какие классы попали в последнюю сцену. Остановить
запуск можно кнопкой «Остановить», она просит подтверждение вторым нажатием,
чтобы случайный клик не прерывал долгую генерацию. В таблице результатов
числа сгруппированы, время показано в секундах, объекты названы по-русски, а
не поставленные в полном объёме виды подсвечены. Путь к папке копируется
кнопкой, отчёт `run.json` лежит там же.

## Если не запускается

| Что видите | Причина | Что делать |
| --- | --- | --- |
| `error: no such command: xtask` | запуск не из корня репозитория | `cd` в корень, там `.cargo/config.toml` |
| `failed to run custom build command` / нет `pkg-config` | нет системных библиотек | шаг 2 быстрого старта |
| `Failed to build event loop: ... neither WAYLAND_DISPLAY nor ... DISPLAY is set` | нет графической сессии (SSH, headless) | запускать с рабочего стола; без окна работает только `--headless` симулятора |
| `cargo --version` ниже 1.97.1 | старый Rust | `source "$HOME/.cargo/env"`, `hash -r`; при системе с `cargo` из apt — поставить rustup |
| окно открылось, но текста нет | не нашёлся шрифт | запускать из корня репозитория либо задать `LIDAR_ASSETS_DIR` |
| окно раннера: пустой список пресетов | не нашёлся каталог пресетов | положить `presets/` рядом с исполняемым файлом либо задать `LIDAR_PRESETS_ROOT` (или общий `LIDAR_PRESETS`) |
| окно раннера: «ui не собран» | фронтенд не собран | шаг 6 быстрого старта |
| сборка падает по памяти | мало RAM | `CARGO_BUILD_JOBS=2 cargo run -p landscapes-generator` |

Проверить, что всё в порядке, можно без окна:

```sh
cargo test -p generation-core                    # быстрые тесты без GPU
cargo run -p terrains-generator -- --list        # печатает названия пресетов
```

## Установка

Этот раздел — дополнения к шагам 1-2 быстрого старта; если всё запустилось,
читать его не нужно.

Нужны **Rust 1.97.1 или новее** (`rust-toolchain.toml`), графическая сессия и
драйвер видеокарты с Vulkan.

Для уже установленного rustup: `rustup update stable`. Если после обновления
используется старый Rust, выполните `source "$HOME/.cargo/env"` и `hash -r`.
Наличие `cargo` из системных пакетов не значит, что версия достаточно новая.

| Задача | Команда |
| --- | --- |
| пересобрать всё | `cargo build --workspace` |
| быстрый запуск после первой сборки | `cargo run --release -p landscapes-generator` |
| проверить код без сборки приложений | `cargo check --workspace` |
| освободить место | `cargo clean` (удалит весь `target/`) |

Первый `cargo build --release` дольше отладочного, зато генерация в окне идёт
быстрее. `cargo check` проверяет код, но не создаёт исполняемых файлов — для
запуска он не подходит.

## Ярлыки

Чтобы запускать приложения из меню, а не из терминала, создайте ярлыки. Команды
выполняются из корня репозитория (там `.cargo/config.toml` объявляет `xtask`):

```sh
cargo xtask launch-shortcuts --apps all          # все шесть приложений
cargo xtask launch-shortcuts --apps generators   # только генераторы
cargo xtask launch-shortcuts --apps runner --desktop
cargo xtask launch-shortcuts --remove            # удалить созданные
```

| ОС | Формат | Куда |
| --- | --- | --- |
| Linux | `.desktop` | `~/.local/share/applications` |
| Windows | `.lnk` | меню «Пуск» → `LiDAR` |
| macOS | `.command` | `~/Applications/LiDAR` |

`--desktop` дополнительно кладёт копию на рабочий стол. `--remove` удаляет
только то, что создал сам xtask.

Ярлык требует Rust и **собирает приложение при первом запуске** — первое окно
появится через несколько минут. Путь к `cargo` записывается в ярлык абсолютным,
поэтому прописывать его в `PATH` графической сессии не нужно.

## Установка раннера датасетов

Раннер можно поставить как обычное приложение — тогда Node.js и Rust не нужны.
Готовые установщики лежат в `installers/` в корне репозитория; в CI они
прикладываются к прогонам (хранятся 14 дней).

| ОС | Файл | Как поставить |
| --- | --- | --- |
| Ubuntu / Debian | `.deb` | `sudo apt install "./installers/LiDAR Dataset Runner_0.1.0_amd64.deb"` |
| Любой Linux | `.AppImage` | `chmod +x "installers/LiDAR Dataset Runner_0.1.0_amd64.AppImage"` и запустить файл |
| Windows | `-setup.exe` | двойной клик, ярлык появится в меню «Пуск» |
| macOS | `.dmg` | открыть и перетащить приложение в `Applications` |

Проверить установку на Ubuntu / Debian:

```sh
apt list --installed | grep dataset-runner   # пакет li-dar-dataset-runner в списке
lidar-dataset-runner                         # запуск из терминала
```

После установки раннер запускается из меню приложений; каталог пресетов лежит
внутри пакета, отдельно класть `presets/` не нужно.

Ограничения:

- установщик есть **только у раннера** — генераторы без Rust не запустятся, для
  них есть ярлыки выше;
- сборка macOS — **только Apple Silicon**, на Intel Mac приложение не
  запустится;
- `.app` не подписан: первый запуск — через контекстное меню «Открыть»
  (Gatekeeper блокирует двойной клик);
- AppImage сам ярлык не ставит — это делает AppImageLauncher или ничего.

## Управление

Все генераторы:

| Клавиша / мышь | Действие |
| --- | --- |
| `R` / `Shift+R` | новый seed / повторить текущий |
| `V` | 3D-модель / облако точек |
| `Tab` | орбитальная / свободная камера |
| `+` / `-` | приближение / отдаление (орбитальная камера) |
| `Ctrl+S` | окно выбора демо-пресетов |
| `Esc` | закрыть окно пресетов |
| ЛКМ + движение, колесо | вращение, приближение |
| ПКМ + движение, `WASD`, `Q/E`, `Shift` | обзор, полёт, вниз/вверх, ускорение |

Дополнительно `M` в `plants-generator` переключает одиночное растение и группу.

`lidar-simulator`:

| Клавиша | Действие |
| --- | --- |
| `←` / `→` | предыдущий / следующий ракурс |
| `Space` | снять кадр с текущей позиции камеры |
| `T` | проход по круговой траектории (72 ракурса) |
| `P` | пауза / продолжить проход |
| `M` | текущий кадр / накопленный результат |
| `C` | сброс накопления и один кадр с позиции сканера |
| `[` / `]` | уменьшить / увеличить шаг сканера |
| `N` | вкл/выкл измерительный шум |
| `X` | сохранить отображаемое облако в PLY |
| `R` / `Shift+R` | новое здание / повторить с тем же seed |
| `V` | всё облако / только отсканированные точки |

`lidar-dataset-runner` (окно с мышью):

| Действие | Что делает |
| --- | --- |
| «Показать сцену» | собрать сцену по рецепту и нарисовать её без записи файлов |
| перетаскивание, колесо | вращение камеры, приближение |
| «Камера» | вернуть исходный ракурс |
| клик по строке таблицы результатов | открыть эту сцену в просмотре |
| «Остановить», второе нажатие | подтвердить остановку запуска |

## Пресеты

Каталог `presets/` — демонстрационные пресеты четырёх категорий; каждый пресет
это папка с манифестом (id, имя, тег `kind`) и конфигурацией генератора. Пресеты
группируются вложенными папками (`is_group: true`). Выбор — в окне `Ctrl+S`;
настройка хранится в `crates/<крейт>/settings/` и в Git не попадает.
Конфигурации территорий ссылаются на id пресетов и групп ландшафтов, растений и
зданий либо на пути внутри соответствующих категорий. Для базового ландшафта
известный `kind` также определяет архетип, пересоздаваемый с текущим seed.

| Категория | Группы | Пресетов |
| --- | --- | --- |
| `landscapes` | водные, сухие | 12 |
| `plants` | деревья, кустарники, трава | 15 |
| `buildings` | частные дома, многоэтажки, хозпостройки | 11 |
| `terrains` | антропогенные, природные (сухие/водные) | 29 |

Пресеты можно перегенерировать скриптами `examples/dump_presets.rs`
соответствующих крейтов.

## Результат

- окно генератора само строит и 3D-модель, и облако точек с классами (по кодам
  LAS); переключение — `V`;
- `lidar-simulator` сохраняет отсканированное облако в PLY (клавиша `X` или
  `--headless --output`), в файл попадают только измеренные точки и их классы;
- раннер датасетов показывает сцену в окне до запуска, а пишет на сцену
  `scene-NNNN.xyz` (строка `класс x y z`) и `scene-NNNN.stats.json`, а на весь
  запуск — `run.json` (рецепт, итоги, ошибки, отмена). Данные в Z-up, поворот
  в Y-up делает потребитель датасета.

## Структура репозитория

```
crates/
  generation-core        общие данные, облака точек, пресеты
  bevy-utils             камеры, UI, выбор пресетов
  landscapes-generator   рельеф и вода
  buildings-generator    здания
  plants-generator       деревья, кусты, трава
  terrains-generator     территории 100×100 м
  lidar-simulator        симуляция сканирования
  lidar-dataset-runner   приложение для датасетов (Tauri + Vue)
  xtask                  служебные команды (ярлыки)
presets/                 демо-пресеты
```

## Разработка

```sh
cargo test --workspace
cargo check --workspace
cd crates/lidar-dataset-runner/ui && npm run test   # тесты интерфейса (vitest)
```

Тесты интерфейса проверяют форматирование чисел и подписи, черновик рецепта,
сводку ошибок формы, подтверждение отмены, прогресс, таблицу результатов и
предпросмотр сцены; в CI они идут до сборки установщиков.

Сборка установщиков идёт в CI на Ubuntu, Windows и macOS; локально на Linux:

```sh
cd crates/lidar-dataset-runner/ui && npm run build && cd -
cd crates/lidar-dataset-runner && npx tauri build --bundles deb -- --locked
```
