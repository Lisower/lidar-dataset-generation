# lidar-dataset-generator

Процедурная генерация сцен и облаков точек для задач LiDAR: рельеф, вода,
растения, здания и целые территории. Каждый генератор строит и данные, и
визуальные 3D-модели, и облака точек (с классами `PointClass` по кодам LAS),
показывает их в окне Bevy и умеет работать как библиотека без окна. Поверх
генераторов `lidar-simulator` симулирует сканирование сцен LiDAR-сканером.

Вся генерация **детерминирована от seed**: одинаковые пресет и seed всегда
дают одинаковый результат — вплоть до облака точек.

## Требования

- **Rust 1.97.1 или новее** (`rust-toolchain.toml`);
- **Bevy 0.20** — нужен Vulkan и графическая сессия;
- Linux: системные зависимости Bevy — см. `wiki/Запуск.md`;
- для сборки установщика раннера — **Node.js 20** и `@tauri-apps/cli`
  (ставится `npm ci` в `crates/lidar-dataset-runner/ui`).

## Структура репозитория

```
├── crates/            # 9 крейтов workspace
│   ├── generation-core        # общие данные, облака точек, пресеты
│   ├── bevy-utils             # камеры, UI, селектор пресетов, пути к ассетам
│   ├── landscapes-generator   # базовый рельеф: грунт + вода
│   ├── buildings-generator    # здания
│   ├── plants-generator       # деревья, кусты, трава
│   ├── terrains-generator     # целые территории 100×100 м
│   ├── lidar-simulator        # симуляция LiDAR-сканирования
│   ├── lidar-dataset-runner   # GUI массовой генерации датасетов (Tauri + Vue)
│   └── xtask                  # служебные команды: ярлыки запуска
├── presets/           # каталог демо-пресетов (4 категории, 41 пресет)
├── wiki/              # документация команды (Obsidian)
└── local/             # локальные заметки (в Git не попадают)
```

## Крейты

### generation-core

Нижний уровень всех генераторов: детерминированные seed-ы (`Seed`,
`GlobalSeed`), занимаемая территория (`Occupancy`), полигональная геометрия,
облака точек (классы, генерация точек по поверхностям, экспорт в `.xyz` —
`класс x y z` на строку), хранение/выбор демо-пресетов и общие горячие клавиши
генераторов (`V`, `R`, `Shift+R`).

### bevy-utils

Общие Bevy-утилиты: орбитальная и свободная камеры (`Tab`), информационные
панели, система окон UI и селектор демо-пресетов (`Ctrl+S`).

### landscapes-generator — базовые ландшафты

Рельеф 100×100 м: «линии-деформации» (уступы, русла, чаши) поверх базовой
плоскости, fBm-шум каменистости с маскированием у воды, лёгкая
термо-/гидро-эрозия, вода (плоскость и ленты вдоль русел наклонных рек) и
водопады. 12 пресетов: равнины, склоны, уступ каньона, ущелье, речки, пруды,
берега, наклонные реки, водопады, холмы.

```sh
cargo run -p landscapes-generator
```

### buildings-generator — здания

От частных домов (прямоугольные, Г-образные, с пристройкой, избушки) до
многоквартирных домов и небоскрёбов: 6 типов крыш, балконы, парапеты, козырьки,
слуховые окна, дымоходы.

```sh
cargo run -p buildings-generator
# или конкретный архетип:
cargo run -p buildings-generator -- --preset rectangular
# rectangular | l-shaped | annex | apartment | skyscraper
```

### plants-generator — растения

Деревья (ель, высокая ель, сосна, лиственное дерево, ива, пальма, пальма с
кокосами), кусты и травы (низкая/высокая). Режимы генерации: одиночное
растение или группа (клавиша `M`).

```sh
cargo run -p plants-generator
```

### terrains-generator — общие территории

Композиция целой территории 100×100 м: ландшафт, деревья, кусты, трава и
здания, расставленные с учётом рельефа и без взаимных пересечений. 12 пресетов:
поле, лес, избушка, склон, террасы, село, городок, речка, пруд, побережье,
наклонная река, водопад.

```sh
cargo run -p terrains-generator            # пресет по умолчанию — поле
cargo run -p terrains-generator village 42 # конкретный пресет и seed
cargo run -p terrains-generator -- --list  # список пресетов
```

### lidar-simulator — симуляция сканирования

Сканирует процедурное здание (из `buildings-generator`): проверяет поле зрения
(90°×70°), дальность (0.1–150 м) и перекрытия стен, крыши и деталей через AABB-
дерево двусторонних треугольников, отбирает один видимый отсчёт на ячейку шага
(по умолчанию 0.25 м) и добавляет измерительный шум. Накопление кадров,
орбитальные траектории, экспорт в PLY.

```sh
# оконный режим:
cargo run -p lidar-simulator
# headless-экспорт:
cargo run -p lidar-simulator -- --headless --source-step 0.06 --scan-step 0.2 \
  --noise-probability 0.02 --noise-extent 0.12 --frames 72 \
  --seed 12648430 --output assets/export/building-scan.ply
# справка по параметрам:
cargo run -p lidar-simulator -- --help
```

В ходе экспорта в PLY попадают только измеренные точки и их классы; одинаковые
seed и параметры дают одинаковый результат. Управление окном — в таблице ниже.

### lidar-dataset-runner — GUI датасетов

Десктопное приложение (Tauri + Vue) для массовой генерации LiDAR-датасетов:
ландшафт 100×100 м, здания, деревья, кусты и трава собираются в **одну общую
сцену**, которая экспортируется одним файлом облака точек на сцену.

Экран приложения — три зоны:

- **рецепт**: число сцен, seed, выбор ландшафта, строки «элемент → пресет →
  количество» (здания, деревья, кусты, трава; списки пресетов отфильтрованы по
  типу элемента), максимальный уклон под объектами, каталог вывода, кнопки
  «Сгенерировать»/«Отменить»;
- **прогресс**: полоса по сценам, точки/с, прошедшее время, разбивка точек по
  классам с цветами из общего `PointClass`;
- **статистика**: строка на сцену (seed, точек, по классам, объекты
  «поставлено/запрошено», размер файла, время) и строка итогов; ошибки сцен —
  отдельным блоком.

Сборка и запуск (фронтенд собирается отдельно, `cargo run` его не собирает):

```sh
cd crates/lidar-dataset-runner/ui && npm install && npm run build
cd - && cargo run -p lidar-dataset-runner
```

Разработка интерфейса с живой перезагрузкой: `cd crates/lidar-dataset-runner/ui
&& npm run dev` и параллельно `cargo run -p lidar-dataset-runner` (окно
откроется на `http://localhost:1420`); `npm run tauri dev` не используется.

Формат вывода — в каталоге, выбранном в форме:

- `scene-NNNN.xyz` — облако сцены, строка `класс x y z`, без заголовка;
- `scene-NNNN.stats.json` — статистика сцены (точки, классы, объекты,
  bbox, размер файла, время, `frame: "z-up"`);
- `run.json` — отчёт запуска: рецепт, разрешённые имена пресетов, итоги,
  ошибки, признак отмены.

Данные экспортируются в **Z-up** — в той же системе, в которой живут
генераторы; поворот в Y-up делает потребитель датасета. Один и тот же рецепт и
индекс сцены дают побайтово одинаковый `.xyz`; разные индексы дают разные сцены.

Каталог пресетов ищется по порядку: переменная окружения `LIDAR_PRESETS_ROOT`,
`presets/` в ресурсах бандла, сам каталог ресурсов, каталог `presets/` рядом с
исходниками. Найденный путь пишется в лог старта и отдаётся в интерфейс; без
каталога пресетов генерация недоступна (пустой список, а не выдуманная
геометрия).

`cargo test -p lidar-dataset-runner` проверяет всю логику генерации;
`cargo test --workspace` теперь требует системных dev-пакетов WebKitGTK
(`libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`).

## Ярлыки и установка

### Ярлыки для разработчика

Одна команда создаёт ярлыки на все шесть приложений (раннер и пять
Bevy-генераторов) в меню приложений текущей ОС:

```sh
cargo xtask launch-shortcuts --apps all            # все шесть
cargo xtask launch-shortcuts --apps generators     # только Bevy-генераторы
cargo xtask launch-shortcuts --apps runner --desktop
cargo xtask launch-shortcuts --remove              # удалить созданные
```

Куда попадают файлы:

| ОС | Формат | Каталог |
| --- | --- | --- |
| Linux | `.desktop` | `$XDG_DATA_HOME/applications` (обычно `~/.local/share/applications`) |
| Windows | `.lnk` | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\LiDAR` |
| macOS | `.command` | `~/Applications/LiDAR` |

`--desktop` дополнительно кладёт копию на рабочий стол, `--remove` удаляет
только то, что записал сам xtask (манифест — `shortcuts.json` в каталоге данных
пользователя).

Ярлыки **требуют Rust и собирают приложение при первом запуске** — это может
занять несколько минут, и так задумано: ярлык запускает `cargo run -p <крейт>` из
каталога крейта. Путь к `cargo` записывается в ярлык абсолютным, потому что меню
приложений не наследует `PATH` из `.bashrc`. Пути с символами `%`, `"`, `$`,
апострофом и обратной косой чертой отвергаются с понятной ошибкой: такие ярлыки
нельзя записать корректно.

### Установка раннера датасетов

Готовые установщики прикладываются к прогонам CI (артефакты хранятся 14 дней):

| ОС | Артефакт | Установка |
| --- | --- | --- |
| Ubuntu / Debian | `.deb` | `sudo apt install ./lidar-dataset-runner_*.deb` |
| Любой Linux | `.AppImage` | `chmod +x` и запуск файла |
| Windows | `-setup.exe` (NSIS) | обычный установщик, ярлык в меню «Пуск» |
| macOS | `.dmg` | перетащить в `Applications` |

Ограничения, о которых лучше знать заранее:

- установщик есть **только у раннера** — Bevy-генераторы без Rust не
  запустятся, для них есть dev-ярлыки выше;
- сборка macOS — **только Apple Silicon** (`macos-latest`), на Intel Mac
  приложение не запустится;
- `.app` не подписан: первый запуск — через контекстное меню «Открыть»
  (Gatekeeper блокирует двойной клик);
- AppImage сам ярлык не ставит — это делает AppImageLauncher или ничего.

## Запуск из корня репозитория

Ассеты (шрифт `fonts/Roboto-Regular.ttf`) ищутся по абсолютному пути: переменная
`LIDAR_ASSETS_DIR`, затем `<каталог exe>/assets`, затем `assets/` крейта. Поэтому
`cargo run -p <крейт>` работает из любого каталога, в том числе из ярлыка:

```sh
cargo run -p landscapes-generator
```

Запуск из каталога крейта (`cd crates/landscapes-generator && cargo run`) тоже
работает и остаётся удобным для отладки.

## Управление генераторами

Общие клавиши (все генераторы):

| Клавиша | Действие |
| --- | --- |
| `R` / `Shift+R` | Новый seed / повторить с тем же seed |
| `V` | 3D-модель / облако точек |
| `Tab` | Орбитальная / свободная камера |
| `Ctrl+S` | Окно выбора демо-пресетов |
| `Esc` | Закрыть окно пресетов |

Дополнительно: `M` — режим генерации растений (одиночный / группа) в
`plants-generator`.

Управление `lidar-simulator`:

| Клавиша | Действие |
| --- | --- |
| `←` / `→` | Кадр из предыдущего / следующего ракурса |
| `Space` | Снять кадр с текущей позиции камеры наблюдения |
| `T` | Проход по круговой траектории (72 ракурса) |
| `P` | Пауза / продолжить проход |
| `M` | Текущий кадр / накопленный результат |
| `C` | Сброс накопления и один кадр с позиции сканера |
| `[` / `]` | Уменьшить / увеличить шаг сканера |
| `N` | Вкл/выкл измерительный шум (2%) |
| `X` | Сохранить отображаемое облако в PLY |
| `R` / `Shift+R` | Новое здание / повторить с тем же seed |
| `V` | Всё облако / только отсканированные точки |

## Пресеты

Каталог `presets/` — демонстрационные пресеты четырёх категорий. Каждый пресет —
папка с двумя файлами:

- `manifest.ron` — id, отображаемое имя, `kind`-тег;
- `config.ron` — сериализованная конфигурация генератора (для ландшафтов —
  «запечённая» геометрия из архетипа, для зданий/растений — параметры).

Пресеты группируются вложенными папками (`is_group: true`). Выбор пресетов —
в окне `Ctrl+S`, настройка хранится в `crates/<крейт>/settings/` и в Git не
коммитится. Террейны ссылаются на пресеты ландшафтов, растений и зданий по
`kind`-тегам.

| Категория | Группы | Пресетов |
| --- | --- | --- |
| `landscapes` | водные, сухие | 12 |
| `plants` | деревья, кустарники, трава | 10 |
| `buildings` | частные дома, многоэтажки | 7 |
| `terrains` | антропогенные, природные (сухие/водные) | 12 |

Пресеты можно перегенерировать/дополнять скриптами `examples/dump_presets.rs`
соответствующих крейтов.

## Тесты и проверки

```sh
cargo test --workspace
cargo check --workspace
cargo test -p xtask
```

Установщики собираются в CI (`.github/workflows/build.yml`) на Ubuntu, Windows и
macOS; локально тот же бандл на Linux:

```sh
cd crates/lidar-dataset-runner/ui && npm run build && cd ..
cd crates/lidar-dataset-runner && npx tauri build --bundles deb -- --locked
```

Разработка настроена на быстрый цикл: зависимости в dev-профиле не
оптимизируются (иначе `cargo check` занимает минуты). Для более быстрой
демонстрационной сборки используйте `--release`.
