# lidar-dataset-generator

Процедурная генерация сцен и облаков точек для задач LiDAR: рельеф и вода,
здания, растения, целые территории и симуляция сканирования. Каждый генератор
показывает результат в окне и умеет работать без окна — как библиотека.

Вся генерация **детерминирована от seed**: одинаковые пресет и seed всегда дают
одинаковый результат, вплоть до облака точек.

## Что можно запустить

| Приложение | Что делает |
| --- | --- |
| `landscapes-generator` | базовый рельеф: грунт, вода, водопады |
| `buildings-generator` | дома, многоквартирные здания, небоскрёбы |
| `plants-generator` | деревья, кусты, трава |
| `terrains-generator` | территория 100×100 м: ландшафт + здания + растения |
| `lidar-simulator` | сканирование сцены LiDAR-сканером |
| `lidar-dataset-runner` | приложение для массовой генерации датасетов |

```sh
cargo run -p landscapes-generator
cargo run -p buildings-generator            # -- --preset rectangular|l-shaped|annex|apartment|skyscraper
cargo run -p plants-generator
cargo run -p terrains-generator             # [пресет] [seed], например: village 42
cargo run -p terrains-generator -- --list   # список пресетов территории
cargo run -p lidar-simulator
```

`lidar-simulator` умеет сохранять скан без окна:

```sh
cargo run -p lidar-simulator -- --headless --frames 72 --seed 12648430 \
  --output assets/export/building-scan.ply
cargo run -p lidar-simulator -- --help
```

Раннер датасетов — отдельное приложение; интерфейс собирается отдельно:

```sh
cd crates/lidar-dataset-runner/ui && npm install && npm run build && cd -
cargo run -p lidar-dataset-runner
```

Для разработки интерфейса: `npm run dev` в `crates/lidar-dataset-runner/ui` и
параллельно `cargo run -p lidar-dataset-runner`.

## Установка

Нужны **Rust 1.97.1 или новее** (`rust-toolchain.toml`), графическая сессия и
драйвер видеокарты с Vulkan. Первая сборка Bevy занимает много времени и места.

Ubuntu / Debian:

```bash
sudo apt update
sudo apt install build-essential pkg-config curl libx11-dev libasound2-dev \
  libudev-dev libxkbcommon-x11-0 libwayland-dev libxkbcommon-dev
```

Для Intel/AMD при отсутствии Vulkan-драйвера: `sudo apt install mesa-vulkan-drivers`.
Для NVIDIA нужен подходящий драйвер NVIDIA.

Rust ставится через `rustup`, если его ещё нет:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs -o /tmp/rustup-init.sh
sh /tmp/rustup-init.sh -y
source "$HOME/.cargo/env"
```

Проверьте `cargo --version`: версия должна быть не ниже 1.97.1. Если после
обновления используется старый Rust, выполните `source "$HOME/.cargo/env"` и
`hash -r`. Наличие `cargo` из системных пакетов не значит, что версия достаточно
новая.

Для сборки установщика раннера дополнительно нужен **Node.js 20** (зависимости
ставятся `npm ci` в `crates/lidar-dataset-runner/ui`).

Последующие запуски используют собранные зависимости. Для более быстрой работы
генераторов можно собрать с `--release`; первая такая сборка займёт дольше. При
нехватке памяти добавьте `CARGO_BUILD_JOBS=2` перед `cargo run`.

## Ярлыки

Чтобы запускать приложения из меню, а не из терминала, создайте ярлыки:

```sh
cargo xtask launch-shortcuts --apps all          # все шесть приложений
cargo xtask launch-shortcuts --apps generators   # только генераторы
cargo xtask launch-shortcuts --apps runner --desktop
cargo xtask launch-shortcuts --remove            # удалить созданные
```

| ОС | Формат | Куда |
| --- | --- | --- |
| Linux | `.desktop` | `~/.local/share/applications` |
| Windows | `.lnk` | меню «Пуск» → `LiDAR` |
| macOS | `.command` | `~/Applications/LiDAR` |

`--desktop` дополнительно кладёт копию на рабочий стол. `--remove` удаляет
только то, что создал сам xtask.

Ярлык требует Rust и **собирает приложение при первом запуске** — первое окно
появится через несколько минут. Путь к `cargo` записывается в ярлык абсолютным,
поэтому прописывать его в `PATH` графической сессии не нужно.

## Установка раннера датасетов

Готовые установщики прикладываются к прогонам CI (хранятся 14 дней):

| ОС | Файл | Установка |
| --- | --- | --- |
| Ubuntu / Debian | `.deb` | `sudo apt install ./lidar-dataset-runner_*.deb` |
| Любой Linux | `.AppImage` | `chmod +x` и запуск файла |
| Windows | `-setup.exe` | обычный установщик, ярлык в меню «Пуск» |
| macOS | `.dmg` | перетащить в `Applications` |

После установки раннер запускается из меню приложений; каталог пресетов лежит
внутри пакета.

Ограничения:

- установщик есть **только у раннера** — генераторы без Rust не запустятся, для
  них есть ярлыки выше;
- сборка macOS — **только Apple Silicon**, на Intel Mac приложение не
  запустится;
- `.app` не подписан: первый запуск — через контекстное меню «Открыть»
  (Gatekeeper блокирует двойной клик);
- AppImage сам ярлык не ставит — это делает AppImageLauncher или ничего.

## Управление

Все генераторы:

| Клавиша / мышь | Действие |
| --- | --- |
| `R` / `Shift+R` | новый seed / повторить текущий |
| `V` | 3D-модель / облако точек |
| `Tab` | орбитальная / свободная камера |
| `Ctrl+S` | окно выбора демо-пресетов |
| `Esc` | закрыть окно пресетов |
| ЛКМ + движение, колесо | вращение, приближение |
| ПКМ + движение, `WASD`, `Q/E`, `Shift` | обзор, полёт, вниз/вверх, ускорение |

Дополнительно `M` в `plants-generator` переключает одиночное растение и группу.

`lidar-simulator`:

| Клавиша | Действие |
| --- | --- |
| `←` / `→` | предыдущий / следующий ракурс |
| `Space` | снять кадр с текущей позиции камеры |
| `T` | проход по круговой траектории (72 ракурса) |
| `P` | пауза / продолжить проход |
| `M` | текущий кадр / накопленный результат |
| `C` | сброс накопления и один кадр с позиции сканера |
| `[` / `]` | уменьшить / увеличить шаг сканера |
| `N` | вкл/выкл измерительный шум |
| `X` | сохранить отображаемое облако в PLY |
| `R` / `Shift+R` | новое здание / повторить с тем же seed |
| `V` | всё облако / только отсканированные точки |

## Пресеты

Каталог `presets/` — демонстрационные пресеты четырёх категорий; каждый пресет
это папка с манифестом (id, имя, тег `kind`) и конфигурацией генератора. Пресеты
группируются вложенными папками. Выбор — в окне `Ctrl+S`; настройка хранится в
`crates/<крейт>/settings/` и в Git не попадает. Территории ссылаются на пресеты
ландшафтов, растений и зданий по тегам.

| Категория | Пресетов |
| --- | --- |
| ландшафты | 12 |
| растения | 11 |
| здания | 7 |
| территории | 12 |

## Результат

- окно генератора само строит и 3D-модель, и облако точек с классами (по кодам
  LAS); переключение — `V`;
- `lidar-simulator` сохраняет отсканированное облако в PLY (клавиша `X` или
  `--headless --output`), в файл попадают только измеренные точки и их классы;
- раннер датасетов пишет на сцену `scene-NNNN.xyz` (строка `класс x y z`) и
  `scene-NNNN.stats.json`, а на весь запуск — `run.json` (рецепт, итоги, ошибки,
  отмена). Данные в Z-up, поворот в Y-up делает потребитель датасета.

## Структура репозитория

```
crates/
  generation-core        общие данные, облака точек, пресеты
  bevy-utils             камеры, UI, выбор пресетов
  landscapes-generator   рельеф и вода
  buildings-generator    здания
  plants-generator       деревья, кусты, трава
  terrains-generator     территории 100×100 м
  lidar-simulator        симуляция сканирования
  lidar-dataset-runner   приложение для датасетов (Tauri + Vue)
  xtask                  служебные команды (ярлыки)
presets/                 демо-пресеты
```
